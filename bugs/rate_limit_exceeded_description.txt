Codex does not perform any internal rate-limiting for its own calls to the OpenAI API, nor does it properly catch and handle OpenAI's `rate_limit_exceeded` error.  Codex needs to either know what OpenAI's rate limits are, and purposefully slow down its own reasoning process just enough to stay within the limits; or else if that is not possible, then Codex needs to properly catch the `rate_limit_exceeded` error message, which lists how long to wait before trying again, and simply sleep for the the specified amount of time rounded up to the nearest whole second.  Subsequent `rate_limit_exceeded` errors should trigger an exponential backoff algorithm, in order to find an acceptable API call rate with as few errors as possible.
